Breaking changes encountered in 0.14 → 1.4:

- The 1.0 release removes `Comments`/`CommentForm` from `emdash/ui`; both post templates now import `emdash/ui/comments`. The initial typecheck captured the removed-export errors.
- Internal middleware, media-runtime and route exports moved under `emdash/internal/`. Removed the old explicit EmDash SSR optimization entries, including `emdash/routes/PluginRegistry` and middleware subpaths. The integration owns prebundling core dependencies. Kept app-specific packages that still caused first-render dependency discovery/reloads in the live runs.
- Native plugins must expose a resolvable descriptor entrypoint. SEO 0.12's `definePlugin` call loses its embedded paths on 1.4, so removing the existing entrypoint/adminEntry workaround caused the production build to fail. Kept it, with an explanatory comment. SEO 0.12 declares an old `emdash ^0.21.0` peer and deprecated capabilities; the latter remain supported throughout 1.x. This upgrade does not claim that upstream has certified the old SEO peer range.
- Migration 087 converts legacy reference fields to relation-backed selections. EmDash 1.4 rejects `where: { service: id }` on these fields, which made service-scoped blocks silently fall back to inline content. All ten block callers now use `getServiceEntries` in the shared CMS helpers package; it reads service selections through `getEmDashReferences`, walks collection pages, propagates cache hints and surfaces query errors. Real HTTP checks reproduce the missing-content failure before the fix, then verify all five block types on both apps, exclusion of another service, and moving a FAQ to another service.
- Generated collection interfaces now derive from slugs (e.g. `PricingPlan` → `Pricing`, `TeamMember` → `Team`). Regenerated types from the copied databases. New image/byline/term types and reference-selection types are generated by 1.4 rather than edited manually.
- `emdash dev` was removed; existing app scripts already use `astro dev`. The refreshed skills now describe the supported command and first-request migrations. `definePlugin` was removed for sandboxed authoring, but these apps' plugins are native, so no plugin-format migration was needed. MCP updates require revision tokens; no MCP publishing/write workflow was changed here.
- EmDash emits a per-build `.emdash/migrations.json`; ignored the generated directory so manifests are rebuilt with the deployment's exact package versions rather than committed as a second source of truth.

Patch decision: **drop** the old `EmDashImage` WebP patch. Upstream now uses AstroImage for local media with dimensions, and buildResponsiveImage/getImage with responsive widths for other eligible sources. The 0.x changelog documents native responsive WebP and direct storage reads; the later image change uses Astro's responsive component. Removed marketing's `imageService: "passthrough"` so its adapter can use the native Cloudflare Images service, as garden already does. Production image optimization needs the adapter's generated IMAGES binding and Cloudflare Images availability; no cloud resource was provisioned or modified in this task.
